# Recorded handshakes

Generated by `scripts/record-handshake.hs` from two modec instances calling
each other, so the payload is known and the timeline is reproducible:

```
cabal exec -- runghc -isrc scripts/record-handshake.hs docs/recordings
```

All files are 8 kHz, 16-bit, mono.

| File | Contents |
|---|---|
| `handshake-answer-side.wav` | 10 s, only what the station that **answered the phone** transmits |
| `handshake-call-side.wav` | 10 s, only what the station that **placed the call** transmits |
| `handshake-both-sides.wav` | the whole call, both directions summed and band limited to 300-3400 Hz, as a tap on the line would hear it |

## Timeline of `handshake-both-sides.wav`

Measured with `modec detect` (which reports "no dominant tone" both for
silence and for two tones of similar level, such as a dual tone or two
live carriers):

| Time | Signal |
|---|---|
| 0.00-1.98 s | silence: the V.25 billing delay |
| 1.98-2.38 s | V.8bis CRe segment 1, the 1375 + 2002 Hz dual tone, 12 dB down |
| 2.38-2.50 s | V.8bis CRe segment 2, 400 Hz |
| 2.92-3.36 s | the caller's ESr and its CL capabilities list, V.21 channel 2 (1650/1850 Hz) |
| 3.58-3.76 s | the answerer's MS mode select, V.21 channel 1 (980/1180 Hz) |
| 4.16-7.14 s | V.25 answer tone, 2100 Hz |
| 7.18-7.86 s | V.22 unscrambled binary 1 on the high channel (2250 Hz) |
| 7.86 s on | both carriers: S1, scrambled ones, then 2400 bit/s data |
| 9.0 s | the text `HELLO BBS` is sent over the link |

Note the role reversal: V.8bis §9.9.3 makes the station that *receives*
the MS message the answering modem, so the 2100 Hz answer tone comes from
the station that placed the call, and appears in `handshake-call-side.wav`
rather than in `handshake-answer-side.wav`.
